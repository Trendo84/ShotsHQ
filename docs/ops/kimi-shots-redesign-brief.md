# ShotsHQ redesign brief for Kimi

You are acting as a brutally honest senior product designer / creative director.

## Context
ShotsHQ has already gone through multiple small polish and honesty-fix cycles, but the core complaint is still valid:

**"The site is still basically the same. Where is the redesign?"**

So this is **not** a copy-edit pass and **not** a light polish pass.
This needs a real redesign direction that would make the difference obvious on first load.

## Product
ShotsHQ is a product for creating App Store screenshots and related creative assets.

## Core problem
The current design is visually striking, but it still feels too:
- brutalist
- loud
- busy
- internal / operator-tool-ish
- cognitively heavy
- aggressive rather than premium
- concept-like rather than like a polished software product

It does not yet feel calm, elegant, highly trustworthy, or obviously premium.

## Desired direction
Reposition ShotsHQ so it feels:
- premium SaaS / product-tool
- calm, refined, modern, confident
- easier to understand in under 10 seconds
- easier to navigate
- more trustworthy
- less visually fatiguing
- more coherent across marketing and app surfaces
- still distinctive, but no longer harsh or poster-like

## High-priority surfaces
Please focus your redesign thinking in this order:
1. homepage
2. pricing
3. templates
4. app shell / topbar / sidebar
5. dashboard
6. projects list
7. /projects/new
8. settings
9. only then deeper project-detail surfaces if needed

## Current issues that still need a strong answer
- The homepage hero is attention-grabbing but not calm or premium.
- Pricing is visually striking but not easy to scan or trust instantly.
- Templates need stronger product framing and gallery presentation.
- Marketing still risks feeling louder than it is persuasive.
- The authenticated app can still feel like an internal tool rather than a polished customer product.
- Dashboard lacks a strong “continue where I left off” hierarchy.
- Projects list needs better scanability, clearer grouping, and more premium presentation.
- /projects/new still needs to feel guided and confidence-building, not sparse/system-ish.
- Settings should feel intentional and trustworthy, not like a holding area for mixed live + future controls.
- Overall the product still overuses visual severity, hard contrast, and aggressive energy.

## Important constraints
- No fake testimonials, logos, ratings, or invented proof.
- Keep the product positioning truthful.
- Avoid generic startup fluff.
- Don’t preserve the current style just because it already exists.
- The answer should be decisive and opinionated, not vague.

## What I want from you
Give me **one strong, coherent redesign brief** for ShotsHQ.

Structure it like this:

1. **Blunt diagnosis**
   - Why the current product still does not read as a true redesign
   - What is structurally wrong with the current design language

2. **New visual direction**
   - palette direction
   - typography direction
   - spacing / density rules
   - surface/card style
   - navigation style
   - motion / visual restraint rules
   - what to remove from the current identity
   - what to preserve, if anything

3. **Product positioning and homepage story**
   - clearer articulation of what ShotsHQ does
   - who it is for
   - what the user should understand in the first 10 seconds
   - better CTA hierarchy
   - better supporting section structure

4. **Page-by-page redesign plan**
   For each of these:
   - homepage
   - pricing
   - templates
   - app shell
   - dashboard
   - projects list
   - /projects/new
   - settings

   Give:
   - the redesign goal
   - the layout / hierarchy changes
   - interaction / UX changes
   - copy or framing changes
   - what would make the difference feel obvious to a user

5. **Design-system rules**
   - practical system guidance so implementation feels coherent, not page-by-page random

6. **What not to do**
   - anti-patterns to avoid so the redesign does not slide back into the same feel

7. **Implementation priority**
   - the order an implementation agent should follow to get the highest visible impact fast

## Tone of the answer
Be direct. Be sharp. Be concrete.
If something should be removed, say so.
If something is too loud, too tactical, too poster-like, or too internal, say that plainly.

## Goal
Your answer should help an implementation agent create a redesign that is obviously different and obviously better — not just “slightly cleaner.”
