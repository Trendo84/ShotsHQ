# v1.1: Playwright auth bypass

## Why

`e2e/wizard.spec.ts` exists with two `test.skip()`-marked specs that
would regression-cover Bug 2's wizard navigation fix. Both are skipped
because `/projects/new` lives inside the `(app)` route group whose
layout (`app/(app)/layout.tsx`) calls `requireUser()`, which hits Clerk.

To run real E2E we need:

1. Middleware (`proxy.ts`) to skip auth when an E2E flag is set
2. `requireUser()` (`lib/auth/clerk.ts`) to short-circuit to a deterministic
   dummy user when the flag is set
3. `getBalance()` and friends to short-circuit to safe defaults
4. A dummy user record seeded in the DB (or stubbed at the query layer)
5. Playwright config that sets the flag when starting the dev server
   (already in place — see `playwright.config.ts:39`,
   `env: { NEXT_PUBLIC_E2E: "1" }`)

Item 5 is done. Items 1–4 weren't scoped into the editor-bug-fix pass
because the wizard fix is small + manually verifiable; the editor bugs
are covered by the 23 existing vitest specs.

## What

Add a `NEXT_PUBLIC_E2E === "1"` short-circuit at three layers, with
deterministic fixtures:

### `proxy.ts`

```ts
if (process.env.NEXT_PUBLIC_E2E === "1") {
  return NextResponse.next(); // middleware passes through
}
```

Single line near the top. No production-mode footgun: the flag is only
ever set by `playwright.config.ts`'s `webServer.env`.

### `lib/auth/clerk.ts`

```ts
const E2E_USER: User = {
  id:               "00000000-0000-0000-0000-000000000001",
  clerkId:          "e2e-fixture",
  email:            "e2e@local",
  stripeCustomerId: null,
  plan:             "free",
  creditBalance:    0,
  createdAt:        new Date(0),
  updatedAt:        new Date(0),
};

export async function requireUser(): Promise<User> {
  if (process.env.NEXT_PUBLIC_E2E === "1") return E2E_USER;
  const user = await getOrCreateDbUser();
  if (!user) throw new Error("unauthorized");
  return user;
}
```

### `lib/db/queries/credits.ts`

```ts
export async function getBalance(userId: string): Promise<number> {
  if (process.env.NEXT_PUBLIC_E2E === "1") return 0;
  // existing impl
}
```

(And similar for `debitCredits` / `getLedgerHistory` — return safe
no-op defaults instead of touching the DB.)

### Playwright spec mocks

For routes that DO write (`POST /api/projects`, `POST /api/ai/*`,
`POST /api/stripe/checkout`), use `page.route()` to intercept and
return canned responses. The schema of those responses is already
documented in the route handlers — straightforward to mock.

## Why not seed a dummy DB user

Tempting, but binds E2E runs to having a Postgres instance available
locally + a migration story for the test DB + cleanup logic. The flag
+ fixture approach is one PR; the DB approach is three.

## Risk

The flag check is at the auth boundary. If `NEXT_PUBLIC_E2E` ever
leaks into production env, the entire app becomes auth-less. Mitigate:

- Add a check in `next.config.ts` (mirror the pattern of the existing
  Clerk-live-key guard): refuse to build a Vercel production deployment
  if `NEXT_PUBLIC_E2E === "1"`. Hard fail. No `STRICT_LAUNCH_CHECKS`
  carve-out — there's no legitimate reason for that flag in prod.
- Document loudly in the affected files: comment block above each
  short-circuit citing this issue.

## Tests

The whole point of this issue: unblock the existing wizard E2E specs.
After this lands:

- `pnpm test:e2e` → green for the two wizard specs in `e2e/wizard.spec.ts`
- `pnpm build` with `NEXT_PUBLIC_E2E=1` → fails fast with a clear
  message (verifying the prod guard works)
